Нужно провести рефакторинг системы описания квестов и диалогов в TypeScript.

ЦЕЛЬ

Сейчас квесты вручную описываются как большой массив DraftScene[], где:

- у каждой реплики вручную задаётся id;
- у каждой реплики вручную задаётся next;
- повторяются background, left, right, music и tone;
- нейтральные выборы создают много промежуточных сцен;
- легко создать отсутствующий переход или дублирующийся id;
- импорт сгенерированных нейросетью диалогов слишком трудоёмкий.

Нужно добавить компактный Quest DSL, который компилируется в существующий Scene[].

ВАЖНЫЕ ОГРАНИЧЕНИЯ

1. Не изменяй публичный тип Scene и текущую игровую систему воспроизведения сцен без крайней необходимости.
2. Итогом компиляции DSL должен оставаться обычный Scene[].
3. Старые квесты должны продолжать работать.
4. Новый DSL нужно внедрить параллельно со старым buildScenes, а не удалять старую систему сразу.
5. Не меняй тексты диалогов, названия флагов, проверки характеристик, звуки, музыку и сюжетные переходы существующего квеста.
6. Сохрани строгую типизацию TypeScript.
7. Не используй any.
8. Не создавай runtime-зависимость от внешних библиотек, если она не требуется.
9. Все внутренние идентификаторы сцен должны создаваться автоматически и детерминированно.
10. Перед изменениями изучи реальные типы Scene, StoryChoice, характеристик, эффектов, отношений, инвентаря и флагов в проекте. Используй существующие названия полей, а не выдумывай несовместимые.

ЗАДАЧА 1. СОЗДАТЬ QUEST DSL

Добавь отдельный модуль, например:

src/.../questDsl.ts

Точное расположение выбери по текущей архитектуре проекта.

DSL должен поддерживать следующие типы узлов:

1. dialogue
2. choice
3. cosmeticChoice
4. timedChoice
5. route

Предлагаемый внешний интерфейс:

const quest = defineQuest({
id: 'small-school',
start: 'start',
defaults: {
background: 'school-yard-night',
left: 'Дмит',
},
nodes: [
dialogue(...),
choice(...),
cosmeticChoice(...),
timedChoice(...),
route(...),
],
})

export const scenes = compileQuest(startIndex, quest)

ЗАДАЧА 2. DIALOGUE

Пример желаемого формата:

dialogue({
id: 'start',
background: 'school-dark-vaz',
cast: ['Дмит', 'Кед'],
lines: [
['Рассказчик', 'После Миньки компания идёт по вечернему Арбекову.'],
['Данз', 'А куда мы вообще идём?', ['Кед', 'Данз']],
['Кед', 'Ты пять минут назад предложил идти куда глаза смотрят.'],
[
'Охранник',
'А НУ СТОЯТЬ!',
{
cast: ['Дмит', 'Охранник'],
sound: 'guard-alert',
tone: 'danger',
},
],
],
next: 'school',
})

Поддержи три формы строки:

1.  ['Данз', 'Текст']

2.  ['Данз', 'Текст', ['Кед', 'Данз']]

3.  [
    'Данз',
    'Текст',
    {
    cast: ['Кед', 'Данз'],
    leftEmotion: '...',
    rightEmotion: '...',
    background: '...',
    sound: '...',
    music: '...',
    tone: '...',
    phoneMessage: '...',
    effects: [...],
    },
    ]

Компилятор должен:

- раскрывать каждый dialogue-блок в отдельные Scene;
- самостоятельно создавать id каждой реплики;
- использовать формат вроде:
  start
  start**1
  start**2
  start\_\_3
- первую реплику блока связывать со второй;
- последнюю реплику связывать с next блока;
- не требовать ручного next у каждой строки;
- наследовать background, cast, music, tone и другие параметры от блока;
- позволять строке переопределить параметры блока.

Не используй номера массива как публичные переходы. Переходы DSL должны осуществляться по строковым id узлов, а затем преобразовываться в числовые индексы Scene[].

ЗАДАЧА 3. CHOICE

Пример:

choice({
id: 'help-choice',
background: 'school-yard-night',
cast: ['Дмит', 'Вадим'],
prompt: 'Что делать с Вадимом?',
options: [
{
text: 'Помочь ему попасть в школу.',
next: 'entry-choice',
effects: [
flag('VADIM_HELP_ACCEPTED'),
relation('Вадим', 1),
],
},
{
text: 'Проводить его домой.',
next: 'vadim-home',
effects: [flag('VADIM_SENT_HOME')],
},
{
text: 'Это не моя проблема.',
next: 'vadim-refused',
effects: [
flag('DMIT_REFUSED_VADIM'),
relation('Вадим', -2),
],
},
],
})

Адаптируй effects к реальным полям StoryChoice или Scene в проекте.

Если существующая система не использует универсальный массив effects, создай строго типизированные DSL-эффекты и на этапе compileQuest преобразуй их в реальные поля:

- flag(name)
- removeFlag(name), если поддерживается;
- relation(character, delta);
- money(delta);
- другие уже существующие игровые эффекты.

Не добавляй несуществующую игровую механику.

ЗАДАЧА 4. ПРОВЕРКИ НАВЫКОВ

Нужен helper:

skill(stat, value)

Пример:

{
text: 'Перелезть через забор.',
check: skill('Ловкость', 5),
next: 'window-success',
failNext: 'window-fail',
}

На этапе компиляции это должно преобразовываться в реальные поля StoryChoice:

- requiredStat;
- requiredValue;
- failNext;
- либо их фактические аналоги в проекте.

Используй реальные типы характеристик проекта.

ЗАДАЧА 5. УСЛОВИЯ ДОСТУПНОСТИ ВАРИАНТОВ

Добавь строго типизированные helpers, совместимые с реальными возможностями игры:

- requiresFlag(flag)
- requiresAllFlags(...flags)
- requiresAnyFlag(...flags)
- requiresMoney(amount)

Пример:

{
text: 'Дать охраннику 200 рублей.',
require: requiresMoney(200),
next: 'guard-bribe',
effects: [money(-200), flag('GUARD_BRIBED')],
}

Если движок сейчас не умеет скрывать варианты выбора по сложным условиям, не ломай архитектуру. В таком случае:

- либо реализуй преобразование в существующие поля;
- либо явно опиши минимальное обратно совместимое расширение StoryChoice;
- добавь тесты этого расширения.

ЗАДАЧА 6. COSMETIC CHOICE

Нужен отдельный тип нейтрального выбора, который не требует вручную создавать несколько веток и возвращать их обратно.

Пример:

cosmeticChoice({
id: 'vadim-tone-choice',
background: 'school-yard-night',
cast: ['Дмит', 'Вадим'],
prompt: 'Что ответить Вадиму?',
continueTo: 'entry-choice',
options: [
{
text: 'Ты умный — ты и говори, куда лезть.',
reply: [
['Дмит', 'Ты умный — ты и говори, куда лезть.'],
['Вадим', 'Умный человек предложил бы пойти домой.'],
['Дмит', 'Не настолько умный.'],
],
},
{
text: 'Без лекций. Покажи самый быстрый вход.',
reply: [
['Дмит', 'Без лекций. Покажи самый быстрый вход.'],
['Вадим', 'Самый быстрый не обязательно самый безопасный.'],
['Дмит', 'Вадим.'],
['Вадим', 'Хорошо. Окно раздевалки.'],
],
},
],
})

Компилятор должен автоматически:

- создать сцену выбора;
- создать отдельную временную ветку для reply каждого варианта;
- автоматически связать реплики внутри reply;
- вернуть каждую ветку в continueTo;
- создать детерминированные внутренние id;
- не требовать ручных id и next для reply.

Пример внутренних id:

vadim-tone-choice**option_0
vadim-tone-choice**option_0**1
vadim-tone-choice**option_1
vadim-tone-choice**option_1**1

Внутренние id не должны конфликтовать с id обычных узлов.

ЗАДАЧА 7. TIMED CHOICE

Пример:

timedChoice({
id: 'chase-balls',
background: 'school-corridor-night',
music: 'school-chase',
tone: 'danger',
cast: ['Дмит', 'Вадим'],
prompt: 'Охранник приближается!',
durationSeconds: 4,
defaultOptionIndex: 3,
options: [
{
text: 'Пнуть коробку с мячами.',
check: skill('Ловкость', 5),
next: 'balls-success',
failNext: 'balls-fail',
},
{
text: 'Просто бежать.',
next: 'chase-route',
},
],
})

Не фиксируй таймер на 10 секундах, как сейчас делает chaseChoice.

durationSeconds из DSL должен действительно попадать в:

choiceTimer.durationSeconds

Проверяй, что defaultOptionIndex находится в пределах массива options.

ЗАДАЧА 8. ROUTE ПО ФЛАГАМ

Пример:

route({
id: 'alcohol-route',
routes: [
['CHAPTER_1_ALCOHOL_HEAVY', 'vadim-heavy'],
['CHAPTER_1_ALCOHOL_BEER', 'vadim-beer'],
['CHAPTER_1_ALCOHOL_SOBER', 'vadim-sober'],
],
fallback: 'vadim-sober',
})

Компилятор должен преобразовать это в существующие:

- nextByFlag;
- fallbackNext.

Route может быть технической сценой без видимого текста, если текущий движок требует Scene для маршрутизации.

Если движок позволяет разрешить route во время компиляции без создания видимой сцены, выбери более безопасный вариант, но не меняй поведение существующих квестов.

ЗАДАЧА 9. КОНТЕКСТ И НАСЛЕДОВАНИЕ

Не определяй background через startsWith(id).

ID должен использоваться только для графа переходов.

background, music, tone, left и right должны задаваться:

- в defaults квеста;
- в конкретном узле;
- в конкретной строке.

Приоритет:

параметры строки
→ параметры узла
→ defaults квеста
→ безопасные значения движка.

Для cast используй удобную DSL-форму:

cast: ['Дмит', 'Вадим']

и преобразуй её в реальные left/right.

Поддержи отсутствие правого персонажа:

cast: ['Дмит']

ЗАДАЧА 10. ВАЛИДАТОР

Создай функцию:

validateQuest(quest)

Она должна проверять до компиляции:

1. Дублирующиеся id узлов.
2. Отсутствующие next.
3. Отсутствующие failNext.
4. Отсутствующие fallback.
5. Переходы на несуществующие узлы.
6. Пустой dialogue.lines.
7. Пустой choice.options.
8. Некорректный defaultOptionIndex.
9. Отсутствие стартового узла.
10. Недостижимые узлы.
11. Конфликты внутренних генерируемых id.
12. Некорректные значения проверок навыков.
13. Отрицательное или нулевое время timedChoice.
14. CosmeticChoice без continueTo.

В режиме разработки ошибки должны содержать понятный путь:

Quest "small-school"
Node "entry-choice"
Option 2 "Перелезть через окно"
Unknown target: "window-succes"
Possible target: "window-success"

Не обязательно реализовывать сложный fuzzy search, если он сильно увеличит объём. Но сообщение должно показывать конкретный узел и вариант.

compileQuest должен вызывать validateQuest либо самостоятельно выполнять такую же проверку перед сборкой.

ЗАДАЧА 11. МИГРАЦИЯ КВЕСТА

После реализации DSL мигрируй только один существующий квест:

smallSchoolQuestScenes

Не переписывай сразу все квесты.

Требования к миграции:

- сохранить порядок и содержание диалогов;
- сохранить все существующие флаги;
- сохранить все проверки навыков;
- сохранить звуки;
- сохранить музыку;
- сохранить таймеры;
- сохранить phoneMessage;
- сохранить background;
- сохранить эмоции;
- сохранить успешные и провальные переходы;
- сохранить итоговое поведение квеста.

Новый код должен выглядеть как:

export const smallSchoolQuestDefinition = defineQuest({
id: 'small-school',
start: 'start',
defaults: {
background: 'school-yard-night',
left: 'Дмит',
},
nodes: [
...
],
})

export const smallSchoolQuestScenes: Scene[] = compileQuest(
smallSchoolQuestStartScene,
smallSchoolQuestDefinition,
)

Старый массив можно временно сохранить в git-истории, но он не должен одновременно использоваться в runtime.
